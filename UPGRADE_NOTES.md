# .NET 8 Upgrade Notes

## Overview
This project has been upgraded from .NET Framework 4.7.2 to .NET 8.

## Major Changes

### 1. Project File Format
- Converted from legacy .csproj format to SDK-style format
- Removed explicit file references (now auto-discovered)
- Simplified project structure

### 2. Target Framework
- **BankDatabaseAccess**: Updated to `net8.0`
- **BankManagementSystem**: Updated to `net8.0-windows` (Windows Forms)

### 3. Package Updates
All NuGet packages have been updated to .NET 8 compatible versions:

| Package | Old Version | New Version |
|---------|-------------|-------------|
| Newtonsoft.Json | 12.0.1 | 13.0.3 |
| log4net | 2.0.8 | 2.0.17 |
| HtmlAgilityPack | 1.8.11 | 1.11.59 |
| Newtonsoft.Json.Bson | 1.0.1 | 1.0.2 |
| Microsoft.EntityFrameworkCore | N/A | 8.0.0 |
| Microsoft.EntityFrameworkCore.SqlServer | N/A | 8.0.0 |
| Microsoft.Data.SqlClient | N/A | 5.1.5 |
| System.Configuration.ConfigurationManager | N/A | 8.0.0 |

### 4. Code Changes

#### Database Connection
- Replaced `System.Data.SqlClient` with `Microsoft.Data.SqlClient`
- Updated connection string to include `TrustServerCertificate=True` for local development
- Added null-coalescing operator for safer configuration access

#### Model Classes
- Added default initializers to string properties to satisfy nullable reference types
- Updated return types to use nullable annotations where appropriate

#### Configuration
- Removed .NET Framework specific `<startup>` section from App.config
- Updated provider name in connection string

### 5. Removed Files
- `Properties/AssemblyInfo.cs` (both projects) - Now auto-generated by SDK

### 6. New Files
- `global.json` - Specifies .NET 8 SDK version
- `Directory.Build.props` - Centralizes common build properties and package versions

## Breaking Changes

### Nullable Reference Types
The project now has nullable reference types enabled. This provides better null safety but may require additional null checks in some areas.

### SQL Client
The migration from `System.Data.SqlClient` to `Microsoft.Data.SqlClient` is generally compatible, but some edge cases may behave differently.

## Build Instructions

```bash
# Restore packages
dotnet restore

# Build the solution
dotnet build

# Run the application
dotnet run --project BankManagementSystem/BankManagementSystem.csproj
```

## Testing Recommendations

1. **Database Connectivity**: Verify all database operations work correctly with the new SQL Client
2. **Configuration**: Ensure connection strings are properly loaded
3. **Windows Forms**: Test all UI functionality thoroughly
4. **Entity Framework**: If using EF Core, test all CRUD operations
